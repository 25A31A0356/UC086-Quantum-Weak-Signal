UC-086 Project Specification

Project Title

Quantum-Enhanced Weak Signal Detection in Noisy Radar/SONAR Signals

1. Project Objective

Develop a small simulation-based proof-of-concept inspired by UC-086.

The prototype investigates whether a small quantum/hybrid machine-learning approach can classify weak synthetic signals buried in noise.

This is an educational/research prototype using simulated data. It is not intended to represent an operational radar or sonar system.

2. Classification Problem

The system performs binary classification:

- Class 0: Noise only
- Class 1: Weak signal + noise

3. SNR Conditions

The prototype will evaluate signal detection under multiple signal-to-noise ratio conditions:

- +10 dB
- +5 dB
- 0 dB
- -5 dB
- -10 dB

The exact experimental results must be generated by the program and must not be manually fabricated.

5. Team Responsibilities

M1 — Integration / Team Lead

- Define project architecture.
- Maintain module compatibility.
- Review pull requests.
- Coordinate the team.
- Resolve integration issues.
- Verify the final end-to-end pipeline.

M2 — Signal Processing

- Generate synthetic signals.
- Add controlled noise.
- Implement SNR conditions.
- Generate the dataset required by M3.

M3 — Feature Engineering

- Extract useful time-domain features.
- Extract useful frequency-domain features.
- Normalize/prepare features appropriately.
- Provide a consistent feature dataset to M4 and M5.

M4 — Classical Machine Learning

- Build the classical ML baseline.
- Train and evaluate the model.
- Calculate accuracy, precision, recall and F1-score.
- Produce predictions and evaluation results.

M5 — Quantum / Hybrid Machine Learning

- Build a small quantum/hybrid classifier.
- Encode the selected features into a quantum circuit.
- Evaluate the classifier using a simulator initially.
- Use compatible data and test samples with M4.

M6 — Experiments / Results

- Run controlled experiments.
- Compare classical and quantum/hybrid models.
- Generate evaluation tables and graphs.
- Prepare final results and presentation material.

7. Data Policy

Only synthetic/simulated data will be used.

No operational radar/sonar data is required for this prototype.

The dataset must contain sufficient information for reproducibility, including the signal/noise class and SNR condition.

8. Fair Model Comparison

The classical and quantum/hybrid models should use:

- The same underlying dataset.
- The same feature representation where practical.
- The same labels.
- The same test samples.
- The same SNR conditions.
- The same evaluation metrics.

Differences in preprocessing or feature reduction must be documented.

9. Evaluation Metrics

The main metrics are:

- Accuracy
- Precision
- Recall
- F1-score
- Confusion matrix

Results should also be examined across different SNR levels.

10. Reproducibility

Experiments should use fixed random seeds where appropriate.

Dataset generation, preprocessing and model evaluation procedures should be documented.

Results must be generated from actual experiments.

11. Quantum Computing Scope

The quantum component will remain small enough to run within the project deadline.

A quantum simulator will be used initially.

The project will not claim quantum advantage, quantum supremacy or superiority unless supported by appropriate experimental evidence.

14. Scientific Integrity

The team must:

- Report actual experimental results.
- Clearly identify limitations.
- Avoid fabricated metrics.
- Avoid unsupported claims of quantum advantage.
- Clearly distinguish simulation from real-world radar/sonar deployment.

15. Definition of Success

The prototype is considered successful if the team can:

1. Generate controlled synthetic weak-signal data.
2. Extract numerical features.
3. Train a classical classifier.
4. Train/evaluate a small quantum/hybrid classifier.
5. Run both models on compatible test data.
6. Compare their measured performance across SNR conditions.
7. Demonstrate the complete pipeline.
8. Explain the limitations and results honestly.
